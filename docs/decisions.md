| 2026-09-25 | SUPERSEDES the row above: test-split flaw-label reconstruction from the CSV is REJECTED - do not use it | Built scripts/validate_reconstruction.py to prove the row above before relying on it. Found and fixed three real bugs (UTF-8 BOM breaking the IMG column key, a combined filename tricking split-inference into dumping all CSV rows into "train", and the CSV's 12-digit zero-padded IDs vs train.json's 8-digit IDs). After all three fixes, reconstruction still only reaches 331-365/23,431 (1.4-1.6%) exact matches on train and 0/7,750 (0%) on val. Root cause: the CSV's IMG numbering is a different ID space entirely, not just different padding - csv TRAIN ids span 0-44,734 (train.json spans 0-23,430) and csv VAL ids span 28,000-44,551, entirely disjoint from val.json's 0-7,749. Filename prefix and the SPLIT column agree with each other (no contradictions found), so both point to the same conclusion: this is very likely the original/global VizWiz corpus image ID, not the quality-issues task's own per-split renumbering, and no crosswalk between the two is provided. Consequence: test-split labels (both flaws and recognisability) are unavailable; the val-split-in-half fallback (fixed seed 42) is required for ALL heads, not recognisability alone |
